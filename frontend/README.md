# PathSnap Evaluator Frontend

This directory contains the evaluator-facing web interface for **PathSnap**, an ML-powered vehicular GPS map-matching and road-route reconstruction system.

## Overview

The interface provides an interactive, dark-mode geospatial dashboard built with HTML5, CSS3, JavaScript (ES6+), and Leaflet.js. It allows evaluators and researchers to visualize noisy GPS observations, inspect candidate snapping projections, and examine continuous reconstructed topological routes generated by our champion XGBoost classifier and Hidden Markov Model (HMM) Viterbi decoder.

## Features

1. **Interactive Geospatial Visualization**:
   - Multi-layer Leaflet rendering with CartoDB Dark Matter basemap.
   - **Raw GPS Polyline & Markers**: Red dashed line indicating actual GPS sensor readings with tooltips showing timestamps and coordinates.
   - **Candidate Snapping**: Cyan circular markers showing the exact orthogonal projection onto the matched road arc, connected to the raw GPS point via thin dashed tether lines.
   - **Reconstructed Route**: Luminous green continuous polyline displaying the full sequence of traversed road arcs, including intermediate segments filled via road graph routing.

2. **Trajectory Benchmarking**:
   - Dynamic selector populated directly from the backend API (`GET /trajectories`), categorized by split (`val`, `student_test`, `train`).
   - Quick one-click benchmark buttons for key trajectories:
     - `00000001` (Validation baseline, 1,315 points, 100% connected)
     - `00000084` (Large validation trajectory, 16,031 points, multi-level overpasses, +18.37% HMM accuracy gain)
     - `00000000` (Student test unseen trajectory, 545 points)
     - `00000052` (Student test unseen trajectory, 1,515 points)
   - Custom GPS file upload support (accepts `.track` or space/comma-separated lon/lat/timestamp files).

3. **Algorithm Comparison**:
   - Interactive toggle between **HMM Viterbi Sequence Decoding** (global optimization) and **Top-1 ML Classification** (pointwise argmax).
   - Real-time adjustment of spatial candidate search radius ($15\text{ m}$ to $120\text{ m}$) and maximum candidate count ($5$ to $40$).

4. **Metrics & Performance Dashboard**:
   - Real-time display of total GPS observations, route distance (km), traversed road arcs, topological connectivity status, and server execution latency.

5. **Point-by-Point Inspection Drawer**:
   - Collapsible bottom drawer displaying point-level tabular details: Point Index, Raw Coordinates, Snapped Coordinates, Matched Arc ID (highlighting points where HMM corrected a naive ML argmax prediction), Error Offset, ML Confidence, and Candidate Count.

## Running the Application

### Option 1: Via FastAPI Unified Server (Recommended)

When the FastAPI server is running, the frontend is mounted automatically at `/ui/`:

```bash
uvicorn api.main:app --host 0.0.0.0 --port 8000
```

Then visit [http://localhost:8000/ui/](http://localhost:8000/ui/) in your browser. Visiting [http://localhost:8000/](http://localhost:8000/) from any browser will also automatically redirect to the interface.

### Option 2: Standalone Static Server

If running separately from the backend:

```bash
cd frontend
python -m http.server 3000
```
Open [http://localhost:3000](http://localhost:3000) (ensure the FastAPI backend is running on port 8000).
